# 今天吃什么 · v112

面向手机的晚饭菜单与本机菜谱账本：浏览 900 道菜、随机配餐、按人数列采购清单、记录自己的菜，并可主动配对分享。

公网入口：https://shitoudaidi.github.io/jintian-chi-shenme/

## 运行与验证

需要 Node.js 22.18+。用仓库锁文件安装：

```sh
npm ci
npm run dev
npm test
npm run lint
npm run build
npm run preview
```

开发与预览使用 4321 端口；`npm run preview:host` 允许同一局域网访问。生产离线能力要在 HTTPS 或 localhost 下使用构建产物验证。不要将本机 node_modules、.local 房间数据库、备份、审片截图或密钥上传到公开仓库。

## v112 界面优化

首页以随机配餐为首要操作：顶部大骰子可直接点击，主按钮提供按压反馈；原有手绘骰子、分类图和双人晚餐插画接入实际布局。手机菜单摘要紧凑显示，桌面菜单摘要放在浏览区旁。首次进入直接使用首页，引导保留在设置入口。今晚结果页先显示菜品，份数、备忘和摇菜历史收进可展开设置。导航使用对应的独立插画，修复此前整张状态图裁切造成的图标不清。

## 本轮整理

- 首页记住搜索条件，移动端提供完整分类、菜单摘要和批量选菜；收藏入口可见。
- 已有菜单再次摇菜时选择补齐或替换，可撤销换桌。
- 账本自动保存编辑草稿，烹饪步骤和倒计时可刷新恢复；损坏数据提供导出与恢复入口。
- 食材名、用量、分数、调味分类与人数换算使用统一规则；已购勾选对应当时的需求，新增需求会变为待购。临时项支持追加、替换与单独删除。
- 同步按字段逻辑修订合并，区分本机保存、云端备份和对方确认；网络请求可取消并有超时。
- 微信扫码进入有明确的外部浏览器引导，跨浏览器链接可携带当前食材；盒马提供单独复制食材按钮。

四套主题保留。设计与插画来自内置生图工具，生成记录见 [design/v106/prompts.md](design/v106/prompts.md)。此前的问题审查保存在 audit 文档中；历史阶段说明以本 README 和发布记录为准。

## 数据会不会串？

默认个人记录保存在各自浏览器，不使用全站共享个人数据。独立访客不会自动看到别人的菜单或账本。同一浏览器不同标签页共享本机记录；共用浏览器的人也会看到同一份数据。

主动加入同一同步房间或导入同步包会共享相关字段。房间号是邀请凭据，不应公开；目前没有账号登录或成员审批。公网版本为静态站点，不部署本地开发房间数据库。完整边界见 [PRIVACY.md](PRIVACY.md)。

换网址、微信切换外部浏览器或换设备不会自动迁移数据；可在“我们”导出/导入备份。照片仍只留本机。

## 明确尚未打通的能力

- 盒马当前可以在部分安卓外部浏览器中打开 App，但不能自动填入搜索，也不能自动加购物车。
- 微信里点击第三方 App 入口显示浏览器打开引导，不承诺直接从微信唤起抖音/盒马。
- 视频 App 路由受实际浏览器和已安装客户端影响，保留官方网页备用入口；不提供视频文件代理或站内完整播放器。
- 公网静态版提供实时配对和同步包；本地服务的版本房间 CAS 不等于公网账号云同步。
- 菜谱数据有整理步骤，尚未对全部 900 道逐道人工核验；构建仍有大数据块提示，legacy 样式尚未全部拆除。

## 结构

- `src/pages`、`src/components`：页面和可操作 UI。
- `src/state`：本机状态与同步控制。
- `src/lib/replica.ts`：逻辑修订与共享字段合并。
- `src/lib/amounts.ts`、`shopping.ts`、`servings.ts`：用量和采购规则。
- `src/lib/stateSchema.ts`、`storage.ts`、`backup.ts`：数据校验、持久化与恢复。
- `server`：仅本地预览的静态服务器与开发房间 API。
- `tests`：Node 数据、并发与手机链接回归测试。
